# LLM Discount Advisor

Статический PoC для одного пользователя: автора, который меняет модели в Hermes `config.yaml` и платит за OpenRouter.

## Критерий успеха

За 14 дней автор хотя бы один раз меняет модель по рекомендации этого сайта и не откатывает изменение. Ноль изменений — честный провал H1, а не повод добавлять фичи.

## Что делает PoC

- раз в сутки получает публичный `/api/v1/models`;
- применяет scope gate до обхода провайдеров: алиасы/non-text/voice, затем G1–G4 и G6;
- получает цены только из `/api/v1/models/{canonical_slug}/endpoints`;
- делает до 8 конкурентных запросов с backoff и логированием 429;
- считает цену провайдера, discounted/base price, overpay, uptime, tiered-pricing flag и reasoning labels;
- строит 4–6 объяснимых карточек для `chat`, `code`, `longdoc`, `bulk`;
- публикует `index.html`, `shortlist.json`, `report.md` и JSON-снапшоты.

## Scope gate

Gate выполняется до endpoint-запросов. `canonical_slug` — ключ семейства модели для benchmark/gate-логики. Endpoint-цена запрашивается по уникальному `id`, поэтому варианты `:free` и `:batch` не сливаются по цене, но не считаются отдельными семействами в acceptance.

- G1: top-20 по intelligence/coding/agentic;
- G2: top-20 по каждому value ratio (качество/цена);
- G3: Design Arena rank ≤7;
- G4: free;
- G6: минимум 6 Design Arena категорий и возраст <180 дней.

G5 по объёму токенов требует авторизованный Data API и намеренно отложен в MVP-1. Отсеянные модели записываются в `data/gate_rejected.json` для ручного просмотра.

## Честный аудит данных

`/models` — источник метаданных, не цены. Его цена — дефолтный провайдер. На GLM 5.2 это давало расхождение примерно в 2.3 раза с более дешёвым надёжным endpoint.

`pricing.discount` появляется только в endpoint-ответе и уже применён к `prompt`/`completion`. База восстанавливается как `price / (1 - discount)`.

`pricing.overrides` не выбрасывается. Карточка показывает `has_tiered_pricing`; подробное моделирование длинного контекста не входит в PoC.

Latency и throughput не используются: в исходном аудите поля были пустыми у 100% проверенных endpoint-ов. `uptime_last_1d` — фильтр `<95%`, а не ранг.

Универсальный `cost per task` не вычисляется: нет распределения длин input/output, cache hit rate, reasoning tokens и retries. Blended price — прокси с допущением фиксированного соотношения: `3:1` для chat/code, `10:1` для longdoc, `1:3` для bulk. Это цена за токены, не обещание стоимости работы.

Reasoning effort меняет объём токенов, хотя ставка токена не меняется. В карточке показаны `default_effort` и `mandatory`; bulk дисквалифицирует `mandatory=true`. Дисклеймер: цена соответствует дефолтному effort.

Скидки часто концентрируются у слабых моделей. Поэтому большая скидка — отдельный статус «не безопасный default», а не автоматическая рекомендация.

## Что сознательно не сделано

Графики, Telegram, change detection и дельты, алерты, watchlists, персонализация, Data API с ключом, поиск, фильтры, аккаунты, backend, БД, фреймворки и система сборки.

История снапшотов накапливается с первого дня, но PoC её не использует. Она предназначена для MVP-1.

## Артефакты

- `data/snapshots/YYYY-MM-DD.json` — нормализованный append-only снимок;
- `data/latest.json` — последний снимок;
- `data/gate_rejected.json` — rejects до endpoint-обхода;
- `shortlist.json` — рекомендации для HTML;
- `report.md` — русский отчёт и ограничения;
- `index.html` — один HTML-файл без сборки;
- `NOTES.md` — ручной лог наблюдений.

## Запуск локально

```bash
python -m unittest discover -s tests -v
python -m advisor.pipeline --no-key
python -m http.server 8000
```

Live-запуск использует публичные endpoint-ы. Ключ OpenRouter для PoC не нужен; секреты не хранятся в репозитории.

## Приёмочный тест

Одно и то же множество моделей и один кеш endpoint-данных прогоняются как полный eligible-набор и как gated-набор. Сравниваются top-10 семейств профиля `code`; ожидается минимум 9 совпадений. Фактический live acceptance от `2026-08-20T08:28:32Z` дал **10/10**, `passed=true`.

### Почему было `97`, а в историческом аудите `77`

Это не «20 новых моделей» в одном и том же измерении. Историческое `388 → 77` относится к каталогу и расчёту аудита от 19 августа 2026 года. На текущем каталоге `/models` было 414 строк, но только 343 уникальных семей; после prefilter — 387 строк и 316 семейств. У 71 строки уже на prefilter-слое общий `canonical_slug` с другой строкой (`:batch`, `:free` и другие варианты).

Старая реализация считала строки `/models`: на текущем каталоге она давала 97 строк gate, но только 69 уникальных семейств. Поэтому сравнение `97` с историческим `77` смешивало даты и единицы счёта. Текущая реализация агрегирует benchmark-сигналы на уровне семейства, но сохраняет все variant rows; endpoint-цена каждого варианта запрашивается отдельно по `id`.

Итог: число `77` не является постоянным контрактом. Для текущего каталога честная контрольная цифра — **76 gated-семейств / 108 variant-строк**, а acceptance — **10/10**. Список `data/gate_rejected.json` хранит причины на уровне variant `id`.

## Деплой

GitHub Actions запускается раз в сутки и коммитит артефакты в `main`. GitHub Pages публикуется из `main` / root. В PoC workflow использует публичные запросы без ключа.

Источник: OpenRouter public API. Бенчмарки, если присутствуют, публикуются как данные, полученные через OpenRouter, с оговорками из `report.md`.
